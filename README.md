# ГИС ВОЛС

Геоинформационная система учёта волоконно-оптических линий связи с функцией
автоматизированной локализации повреждений.

ВКР, КФУ, направление «Программная инженерия».

## Запуск на Windows 10

### 1. Установить Docker Desktop (один раз)

1. Проверьте версию Windows: `Win + R` → `winver`. Нужна сборка **19045** или новее
   (Windows 10 22H2). Если старее — обновите Windows через «Центр обновления».
2. Откройте **PowerShell от имени администратора** и выполните:
   ```powershell
   wsl --install --no-distribution
   ```
   Перезагрузите компьютер.
3. Скачайте Docker Desktop с официального сайта: https://www.docker.com/products/docker-desktop/
   и установите с настройками по умолчанию (галочка «Use WSL 2» должна стоять).
4. Запустите Docker Desktop и дождитесь зелёного статуса «Engine running»
   в левом нижнем углу.

### 2. Получить проект

Проще всего — без git: на странице репозитория на GitHub нажмите зелёную кнопку
**Code → Download ZIP** и распакуйте, например, в `C:\VKR_MAPS`.

(Или, если установлен git: `git clone https://github.com/ThunderTHD/VKR_MAPS.git`)

### 3. Запустить

Дважды щёлкните **`start.bat`** в папке проекта. Первый запуск собирает образы —
5–10 минут, дальше — секунды. Когда всё готово, откроется браузер с адресом
http://localhost:8000

Остановить систему — **`stop.bat`** (данные в базе сохраняются).

### 4. Заполнить тестовыми данными

При запущенной системе дважды щёлкните **`generate.bat`**: создаётся обезличенная
тестовая сеть (≈260 точек, 50 кабелей, 1400 волокон) и демонстрационные пользователи
`admin`, `montazhnik`, `viewer` с паролем `Vols-2026`. Текущие данные сети при этом
**удаляются** — справочники и пользователи остаются.

То же из командной строки:
```bat
copy .env.example .env
docker compose up -d --build
```

### Полезные адреса

| Адрес | Что там |
|---|---|
| http://localhost:8000 | карта (нужен вход) |
| http://localhost:8000/status.html | состояние системы и сводка по базе |
| http://localhost:8000/api/docs | документация API (Swagger) |
| `localhost:5433`, база `vols`, пользователь/пароль `vols` | база для DBeaver / pgAdmin |

### Вход

Демонстрационные пользователи (создаются `generate.bat`): `admin` — администратор,
`montazhnik` — монтажник, `viewer` — только просмотр; пароль у всех `Vols-2026`.
Своего пользователя можно создать командой `create-user` (см. ниже).

### Рисование и прокладка кабелей

Для администратора внизу слева — инструменты **Точка**, **Трасса**, **Кабель**:

- **Трасса** — щёлкайте колодцы по порядку; щелчок по пустому месту ставит новую точку,
  изгиб без колодца — с зажатым Shift. Конец рядом с существующей точкой прилипает к ней.
  Enter — сохранить, Backspace — шаг назад, Esc — отмена.
- **Кабель** — щёлкните начало и конец: путь по трассам соберётся сам (кратчайший).
  Если кабель идёт иначе, щёлкните промежуточные колодцы по порядку.
- В карточке участка: **Форма трассы** (перетаскивание изгибов) и **Вставить колодец**.
  В карточке кабеля: **Изменить**, **Перепроложить**, **Удалить**.

### Муфты, рассветка, кроссы, документы

- В карточке узла (администратор): **Поставить муфту**, **Поставить кросс**.
- В карточке муфты: **Рассветка** — схема сварок. Слева и справа выбираются кабели;
  щёлкните свободное волокно слева, затем справа — сварка. Щелчок по линии — потери,
  примечание, «Разварить». Блок «Сварить подряд» — сразу много волокон.
  Кабель, который проходит муфту транзитом, сначала **разрежьте здесь**.
  Там же — **CSV для Excel** и **Печать**.
- В карточке кросса: **Подключить волокна** (волокна кабеля подряд на порты) и отключение.
- В любой карточке — блок **Документы**: прикрепить схему, паспорт, акт или фото.

### Поиск места повреждения

Кнопка **Повреждение** внизу слева (или «Найти повреждение» в карточке кросса или кабеля):
выберите кросс и порт, к которому подключали рефлектометр, введите расстояние до события —
система пройдёт по сваркам, учтёт укрутку и запасы и покажет место на карте с интервалом
погрешности (±… м, 95 %), колодцы, которые стоит проверить, и из чего складывается ошибка.
В «Дополнительно» — длина измерительного шнура, показатель преломления и показание с
другого конца тракта (интервал станет уже). «Показать трассу» — путь волокна и ожидаемые
события рефлектограммы.

Точность на тестовой сети: `docker compose exec app python -m app.cli localize-experiment`.

### Импорт KML

Меню пользователя → **Импорт KML** (только администратор). Загрузите выгрузку из Google
Earth, проверьте сопоставление папок и замечания на карте предпросмотра, нажмите
«Записать в базу». Повторная загрузка того же файла дублей не создаёт.

Из командной строки (пробный прогон, затем запись):
```bat
docker compose cp "C:\путь\схема.kml" app:/tmp/схема.kml
docker compose exec app python -m app.cli import-kml /tmp/схема.kml
docker compose exec app python -m app.cli import-kml /tmp/схема.kml --commit
```

### Убрать тестовую сеть

Перед работой с настоящими данными дважды щёлкните **`clear_test_data.bat`**: удаляется
всё, что создал `generate.bat`, а импортированное из KML и нарисованное вручную остаётся.

### Команды обслуживания

```bat
docker compose exec app python -m app.cli stats                   :: сколько объектов в базе
docker compose exec app python -m app.cli clear-generated         :: удалить только тестовую сеть
docker compose exec app python -m app.cli generate --seed 7       :: другая тестовая сеть
docker compose exec app python -m app.cli create-user ivanov Пароль123 --role installer --name "Иванов И.И."
```

### Если что-то не так

```bat
docker compose ps          :: какие контейнеры запущены
docker compose logs app    :: журнал приложения
docker compose logs db     :: журнал базы
docker compose down -v     :: остановить и УДАЛИТЬ все данные (начать с нуля)
```

## Структура проекта

```
VKR_MAPS/
├── backend/              серверная часть (Python, FastAPI)
│   ├── app/
│   │   ├── api/          HTTP-маршруты
│   │   ├── core/         настройки, база данных, безопасность
│   │   ├── models/       таблицы (SQLAlchemy + GeoAlchemy2)
│   │   ├── schemas/      форматы запросов и ответов (Pydantic)
│   │   └── services/     бизнес-логика: импорт, граф, локализация…
│   ├── alembic/          миграции базы данных
│   └── tests/            автотесты (pytest, на настоящем PostGIS)
├── frontend/             интерфейс (HTML, JavaScript, Leaflet)
├── tools/                скрипты: генератор данных, обезличивание, прототипы
├── data/samples/         обезличенные примеры данных
├── docs/                 архитектура, модель данных, решения, заметки для ВКР
├── docker-compose.yml    запуск всей системы
├── start.bat / stop.bat  запуск и остановка на Windows
├── generate.bat          тестовые данные и демо-пользователи
├── clear_test_data.bat   удалить тестовую сеть (импорт остаётся)
└── .env.example          настройки (скопировать в .env)
```

## Для разработчика

Тесты и линтер (нужен Python 3.12 и запущенная база):
```bash
cd backend
pip install -e ".[dev]"
set DATABASE_URL=postgresql+psycopg://vols:vols@localhost:5432/vols_test
pytest
ruff check .
```

На каждый push GitHub Actions прогоняет линтер и тесты на PostGIS (`.github/workflows/ci.yml`).

## Данные

Реальные схемы сетей, пакеты ИД, ФИО, IP-адреса и коды клиентов **в репозиторий не
попадают** (см. `.gitignore`). Для разработки и демонстрации используются генератор
тестовой сети и обезличенные копии.
