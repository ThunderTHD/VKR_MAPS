# Этап 3. Карта, фильтры, поиск, карточки, вход в систему — заметки для текста ВКР

**Что сделано.** Веб-интерфейс картографической части: подложка OpenStreetMap, слои
инфраструктуры и кабельной сети, фильтры по оператору и владельцу, поиск, карточки
объектов с переходами между связанными объектами, определение местоположения; вход в
систему с ролями; адаптивная вёрстка для телефона.

**Слои GeoJSON формируются в СУБД.** Каждый слой отдаётся одним SQL-запросом, который
сам собирает FeatureCollection (json_build_object, ST_AsGeoJSON). Строки не проходят
через объекты Python — время ответа 8–26 мс для сети из ~260 узлов и 380 участков.
Поддержан фильтр по видимой области (bbox) — заготовка для масштабирования на реальную
сеть пяти городов.

**Семантика фильтров.** Фильтр по оператору показывает не только кабели оператора, но и
инфраструктуру, которую он использует: участки трасс, по которым проходят его кабели,
узлы на их концах, его муфты, кроссы и узлы доступа. Фильтр по владельцу показывает
инфраструктуру владельца канализации. Такая семантика соответствует задачам эксплуатации:
«где лежат кабели Билайна» и «чья это канализация».

**Отображение.** Векторные слои рисуются на Canvas (быстрее SVG для тысяч объектов),
каждый слой — на своей панели с фиксированным порядком наложения. Участки трасс окрашены
по владельцу (подвес по опорам — пунктиром), кабели — по оператору; муфты и узлы доступа
отмечены значками, узлы доступа — цветом состояния.

**Кластеризация точек — собственная реализация.** На мелком масштабе точки
группируются по сетке экранных ячеек: каждая точка переводится в пиксели текущего
масштаба и попадает в ячейку 56×56 px; ячейка с несколькими точками показывается
кружком с числом, щелчок приближает к ним. Сложность — O(n) на перерисовку. Готовый
плагин Leaflet.markercluster отвергнут: он требует сборки через npm, а собственная
реализация (≈50 строк) проще и прозрачна для пояснения.

**Поиск** по коду и названию узла, адресу, номеру муфты, названию кабеля, hostname и
IP-адресу. Коды колодцев нормализуются: «к348», «к.348» и «к.№348» находят один и тот
же колодец — так инженеры пишут коды по-разному.

**Карточки объектов** (узел, участок, кабель, муфта, кросс, узел доступа) содержат
атрибуты и ссылки на связанные объекты; у муфты — таблица рассветки, у кросса — таблица
портов. Для участка показывается фактическая длина вместе с её источником и
погрешностью — пользователь видит, насколько можно доверять цифре. Выбранный объект
подсвечивается на карте, ссылка на него сохраняется в адресе страницы
(`#obj=cable:5&op=2`), её можно переслать коллеге.

**Безопасность.** Вход по логину и паролю, сессия — подписанный JWT в cookie HttpOnly
(недоступен JavaScript страницы) с SameSite=Lax; изменяющие запросы дополнительно
требуют заголовок X-Requested-With (защита от подделки межсайтовых запросов). Сообщение
об ошибке входа одинаково для неверного логина и пароля — не раскрывается, какие
логины существуют. Все данные сети доступны только после входа.

**Адаптивность.** На телефоне карта занимает весь экран, верхняя панель сжимается,
карточка открывается шторкой снизу (касание ручки разворачивает её), таблица рассветки
прокручивается горизонтально, все элементы управления не меньше 44×44 px.

**Качество.** 47 автотестов (добавлено 27): доступ без входа запрещён, cookie HttpOnly,
подделанный токен отклоняется, все слои — корректный GeoJSON, фильтры по оператору,
владельцу и области, нормализация поиска, карточки всех типов, защита от CSRF.
Интерфейс проверен в браузере в двух размерах: 1440×900 и 393×852 (iPhone 15 Pro).
