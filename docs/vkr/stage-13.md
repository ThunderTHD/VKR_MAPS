# Этап 13. Обмен с ГИС, местные системы координат, подложки, перемычки, PWA — заметки для текста ВКР

**Что сделано.** Этот этап закрывает требования эксплуатации, без которых система не
встраивается в работу организации:
* обмен с профессиональными ГИС и САПР в формате **Shapefile** (импорт и экспорт);
* **местные системы координат** (МСК субъекта, UTM): пересчёт при импорте и экспорте,
  координаты X/Y в карточках, поиск по координатам из проекта;
* **подложки** — сканы и PDF планов, привязанные к карте по опорным точкам;
* **перемычки** между муфтами, кроссами и узлами доступа;
* установка на телефон как приложение (**PWA**) и просмотр сети без связи.

## 1. Shapefile

**Зачем.** Исполнительные съёмки, проекты и выгрузки 5Gis, MapInfo, AutoCAD Map приходят в
Shapefile, а не в KML. Без этого формата сеть приходится перерисовывать вручную.

**Как устроено.** Модуль `services/shapefile_io.py` (~250 строк) читает и пишет набор файлов
.shp (геометрия), .shx (индекс), .dbf (атрибуты dBASE), .prj (система координат),
.cpg (кодировка). Поддержаны точки, мультиточки, линии, полигоны и их Z/M-варианты.
Готовые библиотеки не используются (ADR-41): формат открыт и прост, а GDAL усложнил бы
установку на сервер компании без интернета.

Импорт не дублирует логику KML: `kml/shp_source.py` превращает слои Shapefile в ту же
модель «папки → объекты», что и разбор KML. Слой становится папкой; если в атрибутах есть
поле типа (TYPE, ТИП, СЛОЙ, LAYER) с 2–20 значениями — подпапками. Дальше работает уже
проверенный конвейер этапа 4: автосопоставление папок с типами объектов, предпросмотр с
замечаниями, запись в одной транзакции, защита от повторной загрузки.

Кодировка атрибутов определяется по .cpg, по байту кодовой страницы dBASE, затем пробой
UTF-8; иначе CP1251 — так пишут 5Gis и MapInfo. Русские названия полей при экспорте
кодируются в той же кодировке (ограничение dBASE — 10 байт на имя поля).

Экспорт (`export.to_shapefile`) даёт архив со слоями `tochki` (узлы), `trassa` (участки),
`kabeli` (кабели) и `readme.txt` с описанием полей; можно выгрузить в WGS 84 или в любой
системе из реестра.

## 2. Местные системы координат

**Проблема.** Проектная и исполнительная документация в России ведётся в МСК субъекта
(МСК-16 для Татарстана) — плоских координатах в метрах. Параметры МСК официально не
публикуются; ошибка в них сдвигает сеть на сотни метров.

**Решение (ADR-42).** Реестр `crs_def`: имя, определение (WKT из .prj, строка proj, код
EPSG), признак «показывать в карточках». Параметры берутся из файла .prj, который выгружает
программа, где организация уже ведёт геоданные, — ничего не вводится вручную и не
зашивается в код. Пересчёт делает PostGIS (`ST_Transform` с текстовыми определениями,
внутри — PROJ 9), отдельная библиотека не нужна.

Проверки: определение пересчитывается туда-обратно при добавлении; после импорта
проверяется, что все точки оказались на Земле; координаты в метрах без указанной системы
отвергаются с понятным сообщением.

Где используется:
| Место | Что делает |
|---|---|
| Импорт Shapefile | система из .prj или выбранная в списке |
| Экспорт Shapefile | выгрузка в выбранной системе, .prj пишется автоматически |
| Карточки точек и муфт | «X (север) / Y (восток)» в каждой системе с отметкой |
| Поиск | «X Y» из проекта: пробуются все системы и оба порядка осей, берутся варианты не дальше 50 км от сети |

В российской геодезии X — север, Y — восток, в ГИС-файлах наоборот; в интерфейсе подписи
явные, чтобы не путать.

## 3. Подложки

**Зачем.** У эксплуатации есть бумажные и PDF-планы (ситуационные планы, схемы
канализации, генпланы), которых нет на OpenStreetMap. Показ плана под сетью помогает
сверить трассу и найти колодец.

**Как устроено (ADR-43).** PDF растрируется (pypdfium2, до 4000 точек по длинной стороне),
картинка сохраняется как документ. Пользователь отмечает пары «точка на плане — точка
на карте». По ним методом наименьших квадратов ищется аффинное преобразование
пиксели → метры Web Mercator:

  x = a·px + b·py + c,  y = d·px + e·py + f  (6 неизвестных, ≥3 пары точек)

Аффинное преобразование описывает сдвиг, поворот, масштаб по двум осям и перекос — этого
достаточно для чертежа в одном масштабе. При ≥4 точках система переопределена, и
выводится невязка каждой точки в метрах на местности (с поправкой Меркатора cos φ) и
средняя квадратическая. Большая невязка у одной точки — признак ошибки при отметке.
Точки на одной прямой отвергаются (вырожденная матрица).

В браузере картинка показывается слоем `SkewedImage`: CSS-матрица по трём углам, которая
пересчитывается при каждом сдвиге и масштабировании карты. Прозрачность и включение —
в панели «Слои».

## 4. Перемычки

Перемычка — линия с подписью между двумя объектами (муфта, кросс, узел доступа, точка
сети): патч-корд между кроссами, резерв волокон между соседними муфтами. Инструмент
привязывается к ближайшему объекту в радиусе ~20 пикселей, с приоритетом муфта → узел
доступа → кросс → точка. В трассировке волокна перемычки не участвуют — это пометка на
схеме, а не элемент оптического пути (сварки ведутся в рассветке).

## 5. PWA и работа без связи

**Зачем.** Монтажник открывает систему в колодце, подвале, за городом, где связи нет или
она слабая.

**Как устроено (ADR-44).** `manifest.webmanifest` и иконки позволяют установить систему
на главный экран телефона; service worker (`sw.js`):
* оболочка (HTML, CSS, JS, Leaflet) — «сначала сеть, без связи — кэш»: после обновления
  сразу работает новая версия;
* слои карты и справочники `/api/map/…` — так же; без связи видна сеть на момент последней
  загрузки, на экране — плашка «Нет связи»;
* плитки OpenStreetMap — «сначала кэш», не более 3000 (просмотренные районы);
* правки без связи не принимаются — офлайн-очередь дала бы конфликты правок одной трассы;
* при выходе из системы кэш данных сети удаляется.

Service worker работает только в защищённом контексте — поэтому на этапе 10 вход с
телефона сделан по HTTPS (Caddy с локальным центром сертификации).

## Проверка

* Автотесты: Shapefile — чтение/запись туда-обратно, CP1251 и русские имена полей,
  импорт из плоской системы в метрах через .prj и экспорт в неё с возвратом в WGS 84
  (погрешность < 1 см; в тестах МСК моделируется зоной UTM — параметры настоящей МСК в
  репозиторий не попадают);
  реестр систем координат, поиск по X Y; подложки — точное восстановление известного
  аффинного преобразования, невязки, PDF, права; перемычки — привязка, карточка, удаление;
  файлы PWA и поиск по координатам. Всего в проекте 219 тестов.
* Проверено в браузере (Playwright): загрузка плана, привязка по 4 точкам, показ на
  карте; инструмент «Перемычка»; страницы систем координат, экспорта, импорта; установка
  service worker и открытие карты без связи на эмуляции телефона.

## Ограничения

* Подложка — растр: очень большие листы уменьшаются до 4000 точек по стороне.
* Аффинная привязка не исправляет неравномерные искажения (мятый скан, фото листа под углом);
  для них нужна проективная или полиномиальная привязка.
* Без связи — только просмотр.
